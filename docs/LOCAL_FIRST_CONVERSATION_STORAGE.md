# iOS 本地优先会话存储与离线启动

> 状态：2026-08-01 实现，用户已抽查部分真机场景并确认符合预期；2026-08-02 增加账号上下文代次保护，用户确认测试通过。
> 范围：登录态恢复、账号隔离、会话摘要、消息落库、未读/已读、WebSocket 连接状态。
> 关联代码：`IMDatabase`、`IMSocketManager`、`IMConversationListViewController`、`IMChatViewController`、`IMMainTabBarController`。

## 1. 目标

已经成功登录过的用户，即使服务端不可达，也应满足：

1. App 冷启动后直接进入主界面，不跳登录页。
2. 会话页显示本地会话列表和“未连接/连接中”状态。
3. 已落库的聊天消息可以离线查看。
4. 收发消息、未读、已读和会话设置写入本地后，杀进程重启不回退。
5. 同一设备切换账号时，不读取其他账号的会话或消息。

本方案是“本地先显示、服务端成功后权威收敛”，不是只在内存里保留一次 HTTP 响应。

## 2. 启动与连接流程

```text
读取 IMSessionStore
        │
        ├─ 无有效本地登录态 ──> 登录页
        │
        └─ 有本地登录态
             │
             ├─ IMDatabase.useOwnerUserID(uid)
             ├─ 创建主 Tab / 会话页
             ├─ SQLite 读取本地会话并立即显示
             └─ WebSocket 自动连接与重连
                    ├─ Connected    -> 标题“会话”
                    ├─ Connecting   -> 标题“会话（连接中…）”
                    └─ Disconnected -> 标题“会话（未连接）”
```

会话、通讯录、黑名单、好友关系、群列表和资料页的自动 HTTP 登录/刷新失败只写日志并保留当前内容，不弹“登录失败/重新登录”对话框，也不清理本地登录态。用户主动发起的搜索、保存和好友操作失败仍给出反馈；退出账号必须由用户主动操作。

项目使用 `NSURLSessionWebSocketTask` 长连接。连接关闭、接收失败或写入失败都会进入断线状态，并按 1、2、4……30 秒上限指数退避重连。

## 3. SQLite 数据模型

数据库仍是一个 `Documents/im.sqlite` 文件，但两张业务表都以 `owner_uid` 作为强制查询条件，因此隔离单位是“表内账号命名空间”，而不是每个账号一个数据库文件。

物理分库不是当前正确性的前提，账号哈希目录分库已降级为后续增强项。当前优先保证单库模式下切换账号的异步回调不能串写。

### 3.1 `im_message_local`

保存完整本地消息，包括：

- 消息 ID、会话 ID、收发方、类型、内容、时间和状态；
- `conv_seq`、群昵称、撤回/编辑/置顶派生状态；
- 引用、转发、相册分组、视频封面和失败提示；
- `owner_uid`，所有查询、更新和删除必须携带。

出站消息按 `(owner_uid, conv_id, client_msg_id)` 更新，入站消息按 `(owner_uid, conv_id, conv_seq)` 去重。

### 3.2 `im_conversation_local`

保存会话列表完整摘要：

- 单聊/群聊资料；
- 最后一条内容、类型、发送者和时间；
- `latest_conv_seq`、本人/对端已读位点、未读数；
- 置顶、免打扰、手动未读和列表顺序；
- `(owner_uid, conv_id)` 联合主键；
- 内部水位 `server_snapshot_seq`；
- 独立连续同步游标 `synced_conv_seq`。

`server_snapshot_seq` 表示最近一次服务端权威会话快照已经统计到的消息序号。它不属于 UI 模型，用于防止 HTTP 快照已带未读数后，WebSocket 同步相同历史消息又重复累加未读。

`synced_conv_seq` 只表示该 owner、该会话中不大于该值的消息均已成功处理并持久化。它不能从
本地 `MAX(conv_seq)`、会话 `latest_conv_seq`、实时最大消息或发送 ACK 推导；消息、摘要和该游标
在同一事务提交。完整规则与跨端测试方案见
`../IMServer/docs/CONTINUOUS_SYNC_AND_MULTI_CLIENT_TESTING.md`。

### 3.3 账号上下文与切换代次

`useOwnerUserID:` 返回不可由业务代码构造的 `IMDatabaseAccountContext`，其中绑定：

- 规范化后的 `owner_uid`；
- 当前 `IMDatabase` 实例标识；
- 本次账号激活 generation。

每次主账号激活都会推进 generation，即使退出后重新登录相同 uid，也会产生第二代上下文；A→B→A 同样会使第一代 A 永久失效。子页面只捕获当前上下文，不重复激活。异步任务必须在发起时捕获上下文，并通过 `performWithAccountContext:block:` 访问数据库。校验与数据库操作相对账号切换处于同一临界区，因此只有两种结果：操作完整提交到旧账号后再切换，或切换已经发生、迟到操作被整体拒绝，不存在“校验通过后切到新账号再写入”的窗口。

Socket 连接、会话列表 HTTP 回调、聊天发送回调和详情页本地操作均持有各自创建时的账号上下文。网络层原有 connection generation、旧 task 身份检查、同步集合和未决发送清理继续保留；数据库上下文是最后一道持久化边界，不能替代网络竞态保护。

## 4. 一致性规则

### 4.1 消息与会话摘要同事务

`saveMessage:` 在一个 SQLite 事务中完成：

1. 消息幂等插入或更新；
2. 创建或更新对应会话摘要；
3. 更新最后一条、时间、`latest_conv_seq` 和未读数；
4. 新的未置顶活跃会话移动到未置顶区顶部。

任一步失败都回滚，避免出现“消息存在但会话不见了”或“会话更新但消息丢失”。

### 4.2 权威快照与本地状态分开写

- `replaceCachedConversations:`：只用于成功取得的服务端完整列表，同时推进 `server_snapshot_seq`；空数组会清空当前账号的会话摘要。
- 本地已读、设置和删除使用单会话 SQL 更新，不能用内存数组覆盖整表，也不能冒充服务端快照。

### 4.3 未读去重

一条首次插入的对端消息，只有同时满足以下条件才增加未读：

- `conv_seq` 位于本人 `read_seq` 之后；
- 该消息没有被 `server_snapshot_seq` 表示的服务端快照统计过；
- 不是本人另一设备发来的消息副本。

本地尚无权威快照时，`server_snapshot_seq=0`，乱序补拉的每条未读消息仍会正确计数；同一消息重复推送或聊天页二次保存不会重复计数。

已读位点推进时，只扣减这次实际跨过且已在本地存在的对端消息数量，避免本地消息尚未同步完整时把服务端摘要中的剩余未读错误清零。

### 4.4 新会话兜底

收到一条本地尚无摘要的消息时：

- `g_` 前缀按群聊创建，资料暂用“群聊”；
- 单聊优先取消息收发方；
- 本人其他设备发送的消息没有 `to` 时，从规范化的 `u_<uid>_u_<uid>` 会话 ID 推导对端；
- 服务端恢复后，由完整会话列表补齐昵称、头像、群名和成员数。

### 4.5 派生状态同步

- 最后一条消息被编辑或撤回时，同事务更新会话预览；
- 本人其他设备发来的 read 回执更新本地 `read_seq/unread`；
- 对端 read 回执更新 `peer_read_seq`；
- `conv_update` 的置顶、免打扰、手动未读和删除直接持久化，不依赖会话页当时是否可见。

## 5. UI 刷新规则

`IMSocketManager` 在主线程广播连接状态。会话页必须先注册通知，再调用 `connectToHost:userID:`，防止快速连接时漏掉状态。

工程隐藏了系统 `UINavigationBar`，实际标题由 `IMMainNavigationController` 的 `IMLiquidNavigationBar` 绘制。因此状态变化后除了设置 `self.title`，还必须立即触发导航容器布局同步；否则标题只会在切换页面后更新。

收到消息时，网络层已先完成 SQLite 事务。会话页随后直接重读本地缓存并刷新 UI，HTTP 请求只负责稍后的权威资料收敛。

## 6. 失败恢复策略

- 页面自动 HTTP 登录/刷新失败：保留本地 UI，不弹窗；包括会话、通讯录、黑名单、好友关系、群列表和资料页。
- 用户主动操作失败：保留搜索/保存/好友管理等操作的错误反馈，避免静默吞掉操作结果。
- WebSocket 关闭、接收或写入失败：切到断线状态并自动重连。
- SQLite 消息或摘要任一步失败：记录 `IM.DB` 日志并回滚事务。
- 账号上下文已失效或来自另一数据库实例：记录 `IM.DB` / `IM.WS` 日志并丢弃整个操作，不触碰当前账号数据。
- 服务端恢复：WebSocket 重连后按 `(owner_uid, conv_id)` 持久化的连续游标增量同步；未知游标从 0
  开始，跳号时从空洞前补拉，多页只从本页实际连续提交的位置继续；HTTP 成功后覆盖完整会话资料。
- 离线启动时会先把 SQLite 会话登记到同步集合；重连后同时重放本地 `read_seq`，避免离线阅读状态被下一次服务端快照回退。

## 7. 测试清单

自动化测试集中在 `IMConversationCacheTests`：

- 数据库实例重建后恢复会话；
- 会话和消息按账号隔离；
- 权威空列表只清当前账号；
- 收到消息更新摘要、排序且重复消息不重复加未读；
- 新单聊、新群聊和多端发送副本建立最小会话；
- HTTP 未读摘要与历史同步不重复计数；
- 无服务端快照时乱序补拉仍完整计数；
- 推进已读只扣除实际读过的本地消息；
- 本端发送更新预览但不增加未读；
- 编辑/撤回更新最后一条预览；
- 多端已读和会话设置持久化。
- 连续同步游标按账号/会话隔离，消息和游标原子提交；最大已见序号、ACK 和会话快照不能越级推进。
- 账号切换会丢弃旧登录/Socket 回调并清理旧账号的同步与未决发送状态。
- 同账号重新登录会推进代次；A→B→A 后第一代 A 不可写入 B 或第二代 A；已通过校验的操作与账号切换原子排序。
- 重复权威文件消息可补全本地 `file_name/file_size`。

真机回归至少覆盖：在线登录状态切换、停止/恢复服务端、断网杀进程冷启动、单聊/群聊离线浏览、未读/已读、置顶/免打扰/删除，以及账号 A/B 切换隔离。

## 8. 已知边界

- SQLite 保存媒体消息及远程 URL，但没有下载过的图片、视频和文件在服务器不可达时仍无法打开；完整媒体离线缓存是独立任务。
- 新群聊只有消息而未取得群资料时，离线名称暂显示“群聊”。
- 本轮不迁移旧版未隔离数据；按新安装、无旧数据前提实现。
- 当前仍使用单一 `Documents/im.sqlite` + `owner_uid` 逻辑隔离。账号哈希目录物理分库、按账号删除缓存和单库损坏隔离属于后续增强，不阻塞当前功能迭代。
- Playwright 多浏览器上下文与 Web ↔ iOS 模拟器编排器尚未落地；自动化分层和场景编号见
  `../IMServer/docs/CONTINUOUS_SYNC_AND_MULTI_CLIENT_TESTING.md`。
