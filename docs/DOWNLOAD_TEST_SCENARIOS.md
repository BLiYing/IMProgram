# iOS 手测场景 — 媒体下载 / 门控 / 磨砂占位

> 基于 `../../IMServer/docs/DOWNLOAD_DATA_STORAGE_PLAN.md`（分阶段方案 + §3 状态机 + §6.5 差距表）
> 与 `../../IMServer/docs/MEDIA_PLACEHOLDER_MECHANISM.md`（档 A/档 B 门控机制）。
> 用途：iOS 装机后逐条勾（✅通过 / ❌不符 / ⬜未测）。这些是 UI/交互，单测不覆盖，必须真机手测。
> 三条铁律贯穿全程：① 下载**不跳页**；② **完成即止**（就绪态无中心按钮、绝不自动打开/播放）；③ **手动点击永远优先**于策略。

---

## 0. 前置

1. 后端在跑：`cd ../../IMServer && go run ./cmd/imserver`（改过后端才重启）。
2. 两账号：**发送方**（web 1001 或另一台）+ **接收方 iOS 1003**（本机测试端）。
3. 备好素材：≥4 个视频（含 1 个 **>设置上限**的大视频、1 个 <上限的小视频）、几张图片、几个文件（含 >8MB）。
4. 日志对账（可选但强烈建议）：
   - 后端 `tail -f ../../IMServer/dev-logs/imserver.run.log | grep -E "/uploads/"`（看有没有多余 GET）。
   - iOS `dev-logs/im-ios.log`：`media_gated_render`（门控格用了哪源 thumb/none）、`incoming_media`（thumb 是否到端）、`download_start reason=`。

## 1. 档 A — 聊天气泡门控占位（协调器策略门控）

**前置**：1003 关自动下载 —— 设置 → 数据和存储 → 自动下载媒体文件 → 「使用 Wi-Fi」里把**图片/视频关掉**。

| # | 操作 | 预期 | 勾 |
|---|---|---|---|
| 1.1 | 1001 发**图片** | 气泡显**磨砂毛玻璃**占位 + 中心 ↓ + 尺寸角标；不自动下载 | ⬜ |
| 1.2 | 1001 连发**多个视频**（含大/小） | **每个视频都显磨砂占位**（回归重点：旧 bug 是视频不显模糊图）+ ↓ + 尺寸·时长角标 | ⬜ |
| 1.3 | 点一个视频/图片气泡 | **原地**变进度环 + 已下/总，**不跳页**（铁律①）；下完显真实封面（视频可播） | ⬜ |
| 1.4 | 下载中再点 | 暂停（⏸）；再点继续（Range 续传，进度接上不从 0） | ⬜ |
| 1.5 | 就绪态（已下完）的视频 | **无中心按钮**，点整条才播放（铁律②完成即止） | ⬜ |
| 1.6 | 开自动下载（Wi-Fi 视频开）+ 发 <上限小视频 | 自动下载、直接显封面（非门控）；发 >上限大视频 → 仍门控（超上限不自动） | ⬜ |
| 1.7 | 无 thumb 的老消息（若有） | 门控态留中性灰底 + ↓（不联网兜托） | ⬜ |

**判定点**：1.2 的磨砂来自内嵌 thumb；`im-ios.log` 应见 `media_gated_render ... source=thumb`、`incoming_media ... thumb_len>0`。门控期间**不应**有该视频 `/uploads/...mp4` 或其 `poster.jpg` 的 GET（对照机制文档 §3.2 方案 A）。

## 2. 相册宫格逐格门控（IMAlbumCell）

**前置**：同上关自动下载。1001 发**同批多图/多视频**（相册分组）。

| # | 操作 | 预期 | 勾 |
|---|---|---|---|
| 2.1 | 收到相册宫格 | **逐格**各自门控：每格 ↓ / 尺寸角标 / thumb 磨砂占位 | ⬜ |

| 2.3 | 某格下完 | 该格显真图/封面，点它才进查看器 | ⬜ |

## 3. 详情页两 Tab（媒体宫格 / 文件行三态）

**入口**：聊天详情 → 媒体 / 文件 Tab。详情页 `autoPrefetchEnabled=NO`（浏览历史不顺手全拉）。

| # | 操作 | 预期 | 勾 |
|---|---|---|---|
| 3.1 | 媒体 Tab（有未下载项） | 未下载格显**磨砂**、已下载格显真帧；**不应**因打开 Tab 就把几十条视频拉下来 | ⬜ |
| 3.2 | 点未下载媒体格 | 就地下载（不跳页），下完点开查看 | ⬜ |
| 3.3 | 文件 Tab | 文件行**五态**：未下载(↓)/下载中(环)/暂停(⏸)/失败(↻)/已下载(类型图标+「大小·已下载」) | ⬜ |
| 3.4 | 文件行右侧 | **无配件图标**（↓/✕/⋯ 已全删）；点行=下载/暂停/继续/打开 | ⬜ |
| 3.5 | 长按「下载中/已暂停」文件行 | 菜单出现【取消下载】；取消后回未下载态（**不**误显「已下载」） | ⬜ |
| 3.6 | 长按已下载文件行 | 菜单：转发 / 定位到聊天 / 删除（删除现占位，toast「开发中」） | ⬜ |
| 3.7 | 「定位到聊天」 | pop 回聊天页滚到该条并高亮（pop 动画结束后才滚，不被吞） | ⬜ |
| 3.8 | 暂停态文件行副标题 | 行首带 ⏸ 小图标（与气泡文件暂停态一致） | ⬜ |

**跨页一致**：同一文件在聊天页与详情页共用一个下载态（key=content）；一页下载中，另一页进去看到的是同一进度。

## 5. 档 B — 引用缩略门控（被动预览，只读本地）

**性质**：引用条**不是下载入口**（无按钮/进度）；只读本地、绝不为预览联网。

| # | 操作 | 预期 | 勾 |
|---|---|---|---|
| 5.1 | 引用一条**未下载**的视频/图片 | 输入框引用条 + 发送后气泡引用块显**磨砂小图** | ⬜ |
| 5.2 | 引用一条**已下载**的媒体 | 显**清晰真帧** | ⬜ |
| 5.3 | 引用一条无 thumb 的老媒体 | 显 ▶/🖼 **图标** | ⬜ |
| 5.4 | 防串图：引用视频A(未下载)→立刻取消→引用图片B | 引用条显 **B**，不被 A 的延迟结果盖回 | ⬜ |

**判定点（关键）**：做 5.1 时**不应**触发对应原件/远端抽帧的网络请求 —— 后端日志无该媒体 `/uploads/...` GET。这是档 B 与档 A 最大的行为差别（对照机制文档 §4）。

| # | 操作 | 预期 | 勾 |

## 8. 失败分因 & 边界

| # | 操作 | 预期 | 勾 |
|---|---|---|---|
| 8.1 | 下载一个服务端已清理(404/410)的媒体 | 显「文件已失效」，**不给重试按钮**（点了也不动） | ⬜ |
| 8.2 | 下载中断网 | 暂停/失败态（↻）；恢复网络点 ↻ 从断点续传 | ⬜ |
| 8.3 | 发送中杀 App 再进 | 消息在、进度接上（前台续传；后台续传 background URLSession 属**未做**，见计划 §6.5） | ⬜ |
