# 手测场景 — 媒体下载 / 门控 / 磨砂占位（iOS 基准 + Web 对照）

> 基于 `../../IMServer/docs/DOWNLOAD_DATA_STORAGE_PLAN.md`（分阶段方案 + §3 状态机 + §6.5 差距表）
> 与 `../../IMServer/docs/MEDIA_PLACEHOLDER_MECHANISM.md`（档 A/档 B 门控机制）。
> 用途：装机/开页后逐条勾（✅通过 / ❌不符 / ⬜未测）。这些是 UI/交互，单测不覆盖，必须真机/真浏览器手测。
> 三条铁律贯穿全程：① 下载**不跳页**；② **完成即止**（就绪态无中心按钮、绝不自动打开/播放）；③ **手动点击永远优先**于策略。
> **§1–§10 是 iOS 装机场景；§11 是 Web（im-web）手测场景 + 独有差异**——Web 与 iOS **门控决策一致**（要不要自动拉、按尺寸/单群分档、账号级同步），差异只在**落地与呈现**（浏览器沙盒限制），逐条见 §11.J 差异表。

## 1. 档 A — 聊天气泡门控占位（协调器策略门控）

| # | 操作 | 预期 | 勾 |
|---|---|---|---|
| 1.1 | 1001 发**图片** | 气泡显**磨砂毛玻璃**占位 + 中心 ↓ + 尺寸角标；不自动下载 | ⬜ |

| 1.3 | 点一个视频/图片气泡 | **原地**变进度环 + 已下/总，**不跳页**（铁律①）；下完显真实封面（视频可播） | ⬜ |
| 1.4 | 下载中再点 | 暂停（⏸）；再点继续（Range 续传，进度接上不从 0） | ⬜ |

# 11. Web 端（im-web）手测场景 + 独有差异

> 工程：`/Users/liying/IOSProject/im-web`。**门控决策与 iOS 一致**（`src/download.ts shouldAutoDownload` 逐字段对齐 iOS `IMShouldAutoDownload`）；
> 差异只在**落地与呈现**，皆因浏览器沙盒（无 App 沙盒目录、无 Range 分片下载器、分不清移动/Wi-Fi），非功能缺失——逐条见 §11.J。
> 关键实现符号：`src/App.tsx` 的 `mediaGate`（档 A 判定）/ `onGateTap`（点击路由）/ `startDownload`（文件真进度）/ `passivePreviewSource`（档 B 三态取图，`src/download.ts` 纯函数带单测）。
>
> **本轮对齐修改（2026-08-07）**：把原先"直连原件"的 4 处补进门控 —— **相册宫格逐格门控**（B）、**详情媒体宫格门控**（C）、**引用缩略被动预览**（E）、**会话媒体库被动预览**（F）；并让**打开查看器 = 标记已解门控**（opt-in，之后各处显真帧、刷新仍在）。

## 11.0 前置（Web）

1. 后端在跑：`cd ../../IMServer && go run ./cmd/imserver`（改过后端才重启）。
2. 起 Web：`cd ../../im-web && npm run dev` → 浏览器开 `http://localhost:5173`；**开两个标签页**登录不同 uid（如 **1001 发送方** / **1003 接收方**）互发。
3. **关自动下载**（接收方 1003）：设置 ▸ **数据与存储** → 关「自动下载媒体文件」总开关（或把图片/视频类别的单聊·群聊开关关掉、视频/文件档位调「关」）。图片无大小闸，只能靠**关开关**门控；视频/文件也可靠**超大小上限**门控。
4. 备素材：几张图片、几个视频（含 1 个 <上限、1 个 >上限）、几个文件（含 >3MB）。
5. 日志对账（关键判定手段）：后端 `tail -f ../../IMServer/dev-logs/imserver.run.log | grep "/uploads/"`；Web 开 DevTools ▸ Network 看有没有多余的原件/`poster` 请求。**档 B（引用/媒体库/相册/详情宫格）在未下载态下不应出现对应原件 GET**。

| G.2 | 清缓存后回聊天 | 原「已解门控」的图/视频回**磨砂占位**。**Web 差异**：图/视频的**浏览器 HTTP 缓存字节无法在此清除**（浏览器 LRU 自管）——门控状态位已回退，但点开可能仍秒显（HTTP 缓存命中）；文件 blob 已真删 | ⬜ |

## 11.H 失败分因 & 边界

| # | 操作 | 预期 | 勾 |
|---|---|---|---|
| H.1 | 下载一个已清理(404/410)的**文件** | 显「文件已失效」⊘，**不给重试** | ⬜ |
| H.2 | 下载**文件**中途断网 | 失败态 ↻；恢复网络点 ↻ 重下（**Web 无断点续传，从 0 重来**） | ⬜ |

## 11.J Web ↔ iOS 独有差异一览（**允许的差异，非"不符"**）

| 维度 | iOS | Web | 原因 |
|---|---|---|---|
| 网络分档 | 移动数据 / Wi-Fi 两档独立生效 | **只吃 Wi-Fi 档**（移动数据档存但不生效，仍随账号同步回移动端） | 浏览器分不清移动/Wi-Fi |
| 图片/视频落地 | 下到 App 沙盒目录（持久） | **不下 blob，点=解门控 → `<img/video src=远端>`，靠浏览器 HTTP 缓存持久**（方案 B） | 无沙盒目录；HTTP 缓存白送持久 |
| 文件落地 | App 沙盒（持久，QuickLook 预览） | 应用内**内存 blob**（真进度环）→ **刷新即失效**；显式「下载/另存」才落盘 | 无沙盒；内存 blob 是最轻的一档 |
| 下载进度 | 图片/视频/文件均有环形进度 | **仅文件有环形进度**；图片/视频是浏览器自身加载、无进度 | 方案 B 不经我们的 `fetch` 流 |
| 断点续传 / 暂停 | ✅ Range 续传 + ⏸ | ❌ 无（✕ = 取消重来）；文件状态机**四态**（无「暂停」） | Web 无 Range 分片下载器 |
| 失败分因 | 图片/视频/文件均可「文件已失效」 | **仅文件**分因（404/410→已失效）；图片/视频 404 = broken img，无文案 | 图片/视频无状态机（方案 B） |
| 就绪后打开 | QuickLook 应用内预览 | 可预览类型**新标签预览** / 其余**另存**（`openReadyFile`） | 无 QuickLook；浏览器原生预览兜底 |
| 清缓存 | 三缓存目录 + 图片内存缓存全清、字节真释放 | 清文件 blob + opt-in；**图片/视频 HTTP 缓存字节由浏览器 LRU 自管、清不掉** | 无法编程清浏览器 HTTP 缓存 |
| 设置页 | 三层原生 push 页 | **单页平铺** | 平台控件差异 |
| 无障碍 | 四处 cell 原生 label | `title` 属性 | 平台控件差异 |
| 历史视频预取 | 聊天页对滚过的历史视频按策略预取一次 | **无历史预取**（仅到达/渲染的当前消息按策略判门控） | 取舍：Web 不做滚动预取 |

- **门控决策三端一致**：要不要自动拉、按尺寸/单群分档、账号级同步（`capabilities_update`）——差异只在落地呈现。
- **共同取舍**：`blurhash` 用 tiny-JPEG dataURI（`thumb`）代替（三端一致）；「保存到相册」「预先载入较大视频」为 P1 未做。
